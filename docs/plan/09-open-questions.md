## Policy note (to confirm with the corporate plan admin)

Colleagues would paste tokens from `claude setup-token` into a shared instance. The
Claude Code terms let an end user sign in to the unmodified binary with their own
subscription, including where a platform hosts it, but forbid a developer to collect,
store or intermediate Claude.ai credentials for *their* users. A self-hosted team tool
where each person adds and controls their own token sits between the two readings.
Before inviting colleagues on the corporate plan, have the plan admin confirm it is
acceptable; the API-key provider is the fallback if not.

## Risks

- **Claude Code CLI as the only model path.** Pinned by image build; a CLI change can
  break the headless contract, and there is no second provider until one is needed.
  Mitigation: a probe in `deploy.sh` before rollout; the API adapter is designed
  (04) so it can be built in a session when required.
- **History already contains logins and the employer's organisation name.** Not
  secrets, but visible once public. Decide before opening.
- **Scope of phase 1.** SPA rewrite + accounts + targets + the new look is the
  largest step. If it slips, ship the SPA with v1's two targets first.
- **Colleagues' subscription tokens** — see the policy note.
